Product

Everything around the send.

Notification infrastructure is more than a POST request. Mira covers the queues, isolation, accounting and observability that production apps eventually need.

Isolated projects

Every project owns its subscribers, keys, delivery records, webhooks and quota. Ownership is checked on every request.

One REST API

Register subscribers and send notifications over HTTPS. No proprietary SDK, no vendor lock-in, documented with OpenAPI 3.1.

Async by default

Separate queues for Web Push, FCM, APNs and webhooks. Retries with exponential backoff, without duplicate deliveries.

Delivery truth

Pending, queued, processing, accepted, failed, expired. Mira never claims provider acceptance means the device displayed it.

Quotas that hold

Delivery units are reserved atomically before jobs are queued. Concurrent requests cannot overspend the daily allowance.

Signed webhooks

HMAC-SHA256 signatures, event IDs, replay protection, delivery history and automatic retries on a dedicated queue.

Delivery

A pipeline you can audit.

From authentication to provider response, every stage is recorded. When a notification fails, you get the provider error and the attempt count — not a generic failure.

Quota reserved before queueing. Failed sends are returned to the balance.

Idempotency built in. Reuse a key to safely retry a request without duplicate sends.

Invalid tokens cleaned up. Expired subscriptions stop consuming your quota.

Developers

Integrate in an afternoon.

Two endpoints cover the core loop: register a subscriber, send a notification. Everything else is optional.

  • POST /v1/subscribers accepts web subscriptions and mobile tokens.
  • POST /v1/notifications targets all, a segment or individual subscribers.
  • Consistent JSON errors, request IDs, pagination and idempotency keys.

FAQ

Questions, answered.

Still unsure? Read the developer docs or check the live status.

Do I need an SDK?

No. Mira is API-first and documented with OpenAPI 3.1. Any HTTP client works. Browser clients register subscribers with the publishable key; your backend sends with a secret key.

What counts as a delivery unit?

One unit is one notification sent to one subscriber. Sending to 100 devices consumes 100 units. Retries reuse the original reservation and never charge twice.

Does “accepted” mean the notification was displayed?

No. Accepted means the provider took the message. Display and open events are only recorded when the provider reports them, and are labelled separately in the dashboard.

Can I isolate test and live traffic?

Yes. Every project supports live and test environments with separate keys. Test keys use the mira_sk_test_ prefix and never touch live provider credentials.
